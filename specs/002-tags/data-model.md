# Data Model: DRIVE DNA 보조 태그

1차 `specs/001-drive-dna/data-model.md`에 더하는 것만 적는다.

## 1. 신호 → Tracker 입력 (더함)

| 신호 | Tracker 함수 | 하는 일 |
|---|---|---|
| 크루즈 상태 | `cruise(active: Boolean?)` | null은 크루즈 준비 안 됨(값 없음)이다. null이 아닌 값이 운전 중에 한 번이라도 오면(운전 시작 때 이미 받은 값 포함) 그 운전의 `cruiseMs`는 0 이상이고, 아니면 null이다(위임 결정 D1). 운전 중 true(작동)면 다음 크루즈 값이 올 때까지 시간을 `cruiseMs`에 더하고, 운전 끝에서도 마감한다 |
| 배터리 SOC | `soc(pct: Int, start: Boolean = false)` | 마지막 값을 든다. 운전 시작 때 값이 `socStart`, 끝 때 값이 `socEnd`다. 운전 시작 때 getter로 다시 읽은 값(`start = true`)이 시작 값을 덮는다(구독 첫 값이 엇갈려 올 수 있다, research R8, 코드 리뷰 반영) |
| 와이퍼 | `wiper(on: Boolean)` | `cruise`와 같은 방식으로 `wiperMs`를 센다 |
| 조수석 착좌 | `seat(occupied: Boolean, start: Boolean = false)` | 마지막 값을 든다. 운전 시작 때 값이 `passenger`다. getter 값이 덮는 것은 SOC와 같다 |
| 위치 | `place(lat: Double, lon: Double)` | 마지막 한 점만 든다. 운전 시작 때 비우고, 운전 끝 때 값이 `endLat`·`endLon`이다. 그래서 이번 운전 중에 위치를 하나도 받지 못하면 앞 운전의 끝 점이 아니라 "위치 없음"이다(코드 리뷰 반영) |

- `cruise(active)`에 넣는 값: SDK 값이 null이면 null, `ACTIVATED`면 true, 그 밖(`ENABLED` 등)은 false다.
- `wiper(on)`의 `on`은 `WiperState.ON`인가다.
- 크루즈·와이퍼 시간은 1차 시계(주입)로 잰다.

## 2. Metrics (더하는 칸)

| 칸 | 형식 | 없음(null) |
|---|---|---|
| `cruiseMs` | Long | 크루즈 값을 한 번도 받지 못함 |
| `socStart`, `socEnd` | Int | SOC를 받지 못함 |
| `endLat`, `endLon` | Double | 위치를 받지 못함 |
| `passenger` | Boolean | 착좌를 받지 못함 |
| `wiperMs` | Long | 와이퍼 값을 받지 못함 |

## 3. Limits (더하는 칸)

| 칸 | RELEASE | DEMO |
|---|---|---|
| `longMs` | 30분 | 1분 |
| `longKmh` | 60.0 | 20.0 |
| `rainMs` | 3분 | 30초 |
| `rangeMin` | 20 | 5 |
| `situMin` | 3 | 2 |

크루즈·충전 최소 3번과 기준 비율은 두 빌드가 같다(상수).

## 4. 태그 판정 (`Tags`, 순수)

`Tags.all(oldestFirst: List<Metrics>, l: Limits): List<Tag>`. 숨긴 태그는 목록에 없다. 순서는 크루즈, 충전, 이동 범위, 동승, 빗길이다.

```text
TagId(title, left, right):
  CRUISE("크루즈", "직접 운전형", "크루즈 위임형")
  CHARGE("충전", "한계 활용형", "여유 충전형")
  RANGE("이동 범위", "루틴형", "탐험형")
  PASSENGER("동승", "동승 한결형", "동승 맞춤형")
  RAIN("빗길", "빗길 한결형", "빗길 맞춤형")
Tag(id, value: Boolean?(false=left, true=right, null=보류), fact: String?, withheld: String?)
  name = value?.let { if (it) id.right else id.left }
```

- **판정에 쓰는 기록**: 저장된 `analyzed`가 참인 운전만 쓴다(나의 DNA와 같은 묶음. 처음에는 `Judge.analyzed`를 지금 기준으로 다시 셌으나, 기준이 다른 빌드의 기록에서 나의 DNA와 묶음이 달라져 바꿨다, 코드 리뷰 반영). 충전 찾기만 예외로 모든 운전의 순서를 쓴다(spec Edge Cases의 이유).
- **대상이 최소 수보다 적을 때**(위임 결정 D3): `value = null`, `fact = null`, `withheld` = 표의 "보류 이유" 문장이다.
  - 동승·빗길은 상황 집단(동승·비)이 모자라면 그 문장을 먼저 쓰고, 상황 집단은 충분하고 그 밖 집단이 모자랄 때만 그 밖 집단 문장을 쓴다.
  - 대상이 최소 수 이상이면 `fact`는 늘 있다.
- **중앙값**: 짝수 개면 가운데 두 값의 평균이다.
- **분수 표기**: 퍼센트는 반올림 정수다.

| 태그 | 대상 | 보류 이유(대상 수 모자람) | 판정 | 근거 문장 |
|---|---|---|---|---|
| CRUISE | `cruiseMs != null && durationMs ≥ longMs && avgKmh ≥ longKmh` | "장거리 운전이 n번뿐이에요(3번 필요)" | 비율(`cruiseMs/durationMs`) 중앙값 ≥ 0.5 → right, ≤ 0.15 → left, 사이 → 보류 "크루즈를 쓰는 정도가 운전마다 달라요" | "장거리 운전 n번의 크루즈 비율 중앙값 x%" |
| CHARGE | 이어진 두 운전(모든 운전, 오래된 것부터)에서 `next.socStart − prev.socEnd ≥ 10`, 값은 `prev.socEnd` | "충전이 n번뿐이에요(3번 필요)" | 중앙값 ≥ 40 → right, ≤ 25 → left, 사이 → 보류 "충전하는 때가 그때그때 달라요" | "충전 n번의 충전 직전 배터리 중앙값 x%(집 충전 포함)" |
| RANGE | 분석된 운전 중 `endLat`·`endLon`이 있는 것 | "운전이 n번 쌓였어요(20번 필요)" (시연은 5번) | 새 장소 비율 ≤ 0.10 → left, ≥ 0.30 → right, 사이 → 보류 "새 곳과 늘 가던 곳이 섞여 있어요" | "새 장소 x% · 자주 가는 2곳이 y%" |
| PASSENGER | 분석된 운전 중 `passenger != null && hardAccel != null`. 동승(true)과 혼자(false) 두 집단 | "동승 운전이 n번뿐이에요(3번 필요)" 또는 "혼자 운전이 n번뿐이에요(3번 필요)" (시연은 2번) | §5 비교 | §5 |
| RAIN | 분석된 운전 중 `wiperMs != null && hardAccel != null`. 비(`wiperMs ≥ rainMs`)와 그 밖 | "비 운전이 n번뿐이에요(…)" 또는 "맑은 운전이 n번뿐이에요(…)" | §5 비교 | §5 |

- **숨김**: CRUISE는 분석된 운전 중 `cruiseMs != null`이 하나도 없으면 숨긴다. 나머지는 숨기지 않는다.
- **장소 묶음**(위임 결정 D5): 오래된 것부터 끝난 곳을 본다.
  - 장소의 기준점은 그 장소를 처음 만든 점이고 바뀌지 않는다.
  - 기준점과 직선거리 150m 이하인 장소가 있으면 그중 가장 가까운 장소의 횟수에 더한다.
  - 없으면 새 장소를 만들고 "새 장소" 하나를 센다.
  - 거리는 `Dna.kt`에 새로 두는 `meters(lat1, lon1, lat2, lon2)`다. 같은편 `Pick.kt`의 `xy`와 같은 평면 근사(위도 1도 110,540m, 경도 1도 cos(lat1)×111,320m)이고, cos에는 첫 인자(장소 기준점)의 위도를 넣는다.
  - 장소 목록은 계산 중에만 있고 저장하지 않는다.
  - 상위 2곳 비중은 횟수가 많은 두 장소의 합 ÷ 대상 수다.

## 5. 상황 비교 (PASSENGER·RAIN 공통)

- **지수**: 운전 하나의 지수 = `per10(hardAccel + hardDecel + quickSteers)`. `quickSteers`가 null이면 0으로 본다(1차 역동성 지수와 같다).
- **평균**: s = 상황 집단 평균, n = 그 밖 집단 평균
- **변화** c:
  - n > 0이면 `(s − n) / n`이다.
  - n == 0이면 s == 0일 때 0, 아니면 +∞다.
- **판정**:
  - |c| ≥ 0.25 → right(맞춤형)
  - |c| ≤ 0.10 → left(한결형)
  - 사이 → 보류 "평소와 차이가 애매해요(x%)"
- **근거 문장**(위임 결정 D4). x = |c| × 100을 반올림한 정수이고 부호를 붙이지 않는다. 방향은 낱말로 쓴다. k는 상황 집단의 운전 수다.
  - 맞춤형(|c| ≥ 0.25)과 보류(사이): "{동승|비} 운전 k번의 역동성 지수가 평소보다 x% {낮아요|높아요}"
  - 한결형(|c| ≤ 0.10): "{동승|비} 운전 k번의 역동성 지수가 평소와 비슷해요(차이 x%)"
  - 평소 0·상황 0(c = 0): "{동승|비} 운전 k번의 역동성 지수가 평소와 같아요"
  - +∞: "평소엔 급한 조작이 없었는데 {동승|비} 운전 k번에선 있었어요"
  - 보류의 `withheld`: "평소와 차이가 애매해요(차이 x%)"

## 4-1. 판정 예시 (사용자 문서에서 옮김, SC-007)

모두 `Limits.RELEASE` 기준이다. 테스트는 이 값으로 기록을 만들어 `Tags.all`의 결과를 본다.

| 태그 | 사람 | 입력 | 기대 |
|---|---|---|---|
| 크루즈 | 갑 | 장거리 운전 3번, 크루즈 비율 70%·65%·80% | 크루즈 위임형 |
| 크루즈 | 을 | 5%·0%·10% | 직접 운전형 |
| 크루즈 | 병 | 60%·5%·30% | 보류 |
| 이동 범위 | 갑 | 30번 모두 집·회사(새 장소 2번 7%, 상위 2곳 100%) | 루틴형 |
| 이동 범위 | 을 | 집 10·회사 8·한 번씩 간 곳 12(새 장소 14번 47%, 상위 2곳 60%) | 탐험형 |
| 이동 범위 | 병 | 집 14·회사 12·한 번씩 간 곳 4(새 장소 6번 20%, 상위 2곳 87%) | 보류 |
| 충전 | 갑 | 충전 직전 배터리 55%·48%·60% | 여유 충전형 |
| 충전 | 을 | 18%·12%·22% | 한계 활용형 |
| 충전 | 병 | 45%·15%·30% | 보류 |
| 동승 | 갑 | 혼자 운전 지수 평균 100 대비 동승 70(−30%) | 동승 맞춤형 |
| 동승 | 을 | 100 대비 97(−3%) | 동승 한결형 |
| 빗길 | 갑 | 맑은 운전 100 대비 비 70 | 빗길 맞춤형 |

- 사용자 문서의 상황 예시는 동승·비를 나누지 않았다. 같은 숫자를 동승과 빗길에 각각 넣는다.
- 이동 범위 갑의 문서 값(새 장소 3%·상위 2곳 85%)은 장소마다 첫 방문을 새 장소로 세면 함께 나올 수 없다(두 곳이면 이미 2번). 같은 판정이 나오는 값으로 바꿨다.

## 6. 기록 형식 (1차 §7 바꿈)

- 한 줄 20칸이다. 1차 13칸 뒤에 `cruiseMs, socStart, socEnd, endLat, endLon, passenger(1/0), wiperMs`가 붙는다.
- 13칸 줄도 읽는다. 새 칸은 모두 null이다.
- 그 밖의 칸 수는 건너뛴다(1차처럼).
- **로그**(위임 결정 D2): `WatchService`의 "운전 끝" 로그는 `endLat`·`endLon`을 지운 Metrics를 쓰고 뒤에 "위치 있음" 또는 "위치 없음"을 붙인다.
