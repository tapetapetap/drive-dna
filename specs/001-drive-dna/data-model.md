# Data Model: DRIVE DNA

모든 시각은 밀리초다. 운전 중 시각은 `SystemClock.elapsedRealtime()`(실제 시간), 기록 시각은 벽시계다. 첫 앱과 달리 시계를 빠르게 하지 않는다(research R4).

## 1. 신호 → Tracker 입력

| 입력 | 값 | 처리 |
|---|---|---|
| `gear(parked: Boolean, reverse: Boolean)` | P 여부, 후진 여부 | P→P가 아님: 운전 시작. P가 아님→P: 운전 끝. 첫 값은 기준점이다. 운전 도중 시작된 운전은 세지 않는다. 후진 중 핸들 조작은 세지 않는다 |
| `km(v: Float)` | 누적 주행거리 | 표본 `(t, km)`. 직전보다 작은 값은 버리고, 속도 표본을 비운 뒤 그 값부터 다시 잰다 |
| `brake(on: Boolean)` | 페달 밟음 | 꺼짐→켜짐이 1번 |
| `steer(deg: Float)` | 조향각 | 표본 `(t, deg)`. 회전은 절댓값으로, 빠른 조향은 부호 있는 각도의 변화 폭으로 본다(부호가 콘솔과 반대여도 상관없다) |
| `turn(side: Int)` | 방향지시등(−1 왼쪽, 0 꺼짐, 1 오른쪽) | 켜거나 방향을 바꾼 시각을 기억한다 |
| `batteryWh(v: Float)` | 배터리 잔량(Wh) | 운전 시작 값과 마지막 값 |

운전 중에만 센다. 운전 시작 때 이미 켜져 있던 브레이크·방향지시등은 운전 시작 시각에 켜진 것으로 본다. 운전 전에 켰다 끈 방향지시등은 쓰지 않는다.

**받음과 받지 못함**: SDK는 구독 직후 현재 값을 한 번 보내 준다(첫 앱에서 확인). 그래서 운전이 끝날 때까지 값이 한 번도 오지 않은 신호는 "받지 못함"으로 본다. 구독 호출이 실패한 경우도 같다.

## 2. 지표 (Metrics, 운전 하나)

| 필드 | 정의 |
|---|---|
| `endedAt` | 운전이 끝난 시각(벽시계 ms). WatchService가 저장할 때 채운다 |
| `durationMs` | P가 아님 → P 시간 |
| `km` | 운전 중 주행거리 증가의 합(줄어든 값 제외) |
| `movingMs` | 5km/h를 넘는 추정 속도 표본이 올 때마다, 직전 속도 표본과의 간격을 더한 합 |
| `avgKmh` | `km / movingMs`(시간 단위), 움직인 시간이 0이면 0 |
| `hardAccel` | 추정 가속도가 2.5 m/s² 이상이 된 구간 수. 1.0 m/s² 아래로 내려가야 다음 구간으로 센다 |
| `hardDecel` | 추정 가속도가 −3.0 m/s² 이하가 된 구간 수. −1.0 위로 올라가야 다음 구간 |
| `brakes` | 브레이크를 밟은 횟수 |
| `turns` | 조향각 절댓값이 90° 이상이 된 횟수. 45° 아래로 내려가야 다음 회전. 서 있거나(추정 속도 5km/h 이하) 후진하며 돌린 핸들(주차)은 세지 않는다. 서서 돌려 둔 채 출발하면 움직이기 시작한 뒤 첫 조향 표본에서 센다 |
| `early` | 큰 회전 중, 회전 시작(절댓값이 처음 90°가 된 순간)보다 1.5초 이상 전에 방향지시등을 켰고 그때 아직 켜져 있거나 켠 지 10초 안인 회전 수. 꺼진 신호는 회전 하나에만 쓴다 |
| `quickSteers` | 1초 창(창 시작 때 유지되던 값 포함) 안에서 부호 있는 조향각의 최대−최소가 90° 이상인 순간. 마지막으로 센 때부터 2초 안은 세지 않는다. 서 있거나 후진 중이면 세지 않는다 |
| `speedCv` | 움직이는 동안(5km/h 초과)의 추정 속도 표본의 모집단 표준편차 ÷ 평균. 표본이 3개 미만이면 없음 |
| `kwhPer100` | (시작 잔량 − 마지막 잔량)Wh ÷ 1000 ÷ km × 100. 줄지 않았거나, 잔량이 없거나, 거리가 0이면 없음 |
| `analyzed` | 짧은 운전(§3)이 아니면 참. WatchService가 저장할 때 채운다 |

추정 속도와 가속도
- 주행거리 표본이 올 때마다 그 시각에서 2초 이상 앞선 가장 가까운 표본과 비교해 속도를 낸다: (km 차 ÷ 시간 차) × 3,600,000 → km/h
- 가속도는 지금 속도와 2초 이상 앞선 속도 표본의 차이 ÷ 시간 차(m/s²)다.
- 주행거리 표본이 끊겨도 따로 처리하지 않는다. 다음 표본이 오면 2초 이상 앞선 표본(끊기기 전 표본)과 비교하므로, 그 사이의 평균 속도가 된다.

신호를 받지 못하면(§1) 그 신호로 만드는 지표는 0이 아니라 없음이다.

| 받지 못한 신호 | 없음이 되는 지표 |
|---|---|
| 조향각 | `turns`, `early`, `quickSteers` |
| 방향지시등 | `early` |
| 브레이크 | `brakes` |
| 배터리 잔량 | `kwhPer100` |
| 주행거리 | 거리가 0이라 모든 운전이 짧은 운전이 된다(분석하지 않음) |
| 주행거리 값이 거침(Float 최소 단위가 2m 초과, 32,768km 이상) | `hardAccel`, `hardDecel`, `speedCv`. 2초 창 속도가 반올림 잡음이 되기 때문이다 |

## 3. 축 판정 (Axis)

축 값은 −1(앞 글자)부터 +1(뒤 글자)까지다. 0 이상이면 뒤 글자다. 보류면 값이 없고, 이유를 남긴다.

| 축 | 앞 / 뒤 | 지표 | 값 | 보류 조건(출시 / 시연용) |
|---|---|---|---|---|
| 역동성 `DYN` | G / D | 10km당 (hardAccel + hardDecel + quickSteers) = `idx`. 브레이크 횟수는 교통 상황의 영향이 커서 넣지 않는다(관측 문장에만) | `clamp((idx − 3) / 3)` | 급가감속 없음(주행거리 거침), quickSteers 없음, km < 2 / 0.3 |
| 대응 방식 `RES` | P / R | `early / turns` = `share` | `clamp((0.6 − share) / 0.4)` | turns·early 없음, turns < 3 / 2 |
| 주행 리듬 `RHY` | S / F | `speedCv` | `clamp((cv − 0.35) / 0.25)` | 주행거리 거침, movingMs < 3분 / 30초, cv 없음 |
| 운전 목적 `PUR` | E / C | `kwhPer100` | `clamp((kwh − 16) / 6)` | kwhPer100 없음, km < 2 / 0.3 |

- `clamp`는 −1~+1로 자른다. 기준 수치(3, 0.6, 0.35, 16)는 잠정이다. 출발·정지 구간 때문에 고르게 달려도 변동이 0.3 안팎이라 리듬 기준은 0.35다.
- 보류 조건은 표의 왼쪽부터 본다. 신호 없음이 먼저다. 보류 이유 문장은 조건마다 다르다(contracts §3).
- `speedCv`가 없는 것은 움직인 표본이 3개 미만일 때라, 이유는 움직인 시간이 짧은 경우와 같다.
- **짧은 운전**: durationMs < 3분 또는 km < 1(시연용 30초, 0.2km). 분석하지 않는다. 지표는 모두 저장하고 화면에는 길이만 보인다.

## 4. 유형 (TypeCode)

- 축 순서대로 글자를 잇는다(`DYN`, `RES`, `RHY`, `PUR`). 보류는 "·"다. 예: `GPSE`, `GP·E`.
- 네 글자가 모두 있으면 별칭이 있다(contracts §4).

## 5. 나의 DNA (Profile)

- 분석된 기록 중 최신 10개로 만든다. 축마다 보류가 아닌 값의 평균이고, 쓸 값이 없으면 그 축은 보류다.
- `drives`: 사용한 기록 수(10개 이하).
- **차이**: 이번 운전 바로 전까지의 Profile과 이번 운전 값을 비교한다. 두 값이 다 있는 축 중 |차이|가 가장 크고 0.5 이상이면 그 축 하나를 알린다.
- 다시 보기(지난 운전)에서도 같다. 그 운전보다 앞선 분석된 기록 10개로 만든 Profile과 비교한다.
- |차이|가 같으면 축 순서(DYN → RES → RHY → PUR)로 고른다.

## 6. 코칭 (Coach)

후보마다 "기준 대비 비율"을 내서 가장 큰 하나를 고른다(비율이 1 이상인 후보 중). 비율이 같으면 표의 위쪽이다. 없으면 기본 문장이다. 문장은 contracts §5.

| 후보 | 비율 |
|---|---|
| 급감속 | 10km당 hardDecel ÷ 1 |
| 급가속 | 10km당 hardAccel ÷ 1 |
| 빠른 조향 | 10km당 quickSteers ÷ 1 |
| 방향지시등 | turns ≥ 2일 때 (1 − early/turns) ÷ 0.4 |
| 속도 변동 | speedCv ÷ 0.35 |
| 전력 | kwhPer100 ÷ 18 |

## 7. 운전 기록 저장 (Records)

- SharedPreferences "records"의 키 `drives`에 둔다.
- 운전 하나가 한 줄이고, 필드는 쉼표로 나눈다. 숫자만 들어가서 이스케이프가 필요 없다.
- 순서: `endedAt, durationMs, km, movingMs, hardAccel, hardDecel, brakes, turns, early, quickSteers, speedCv, kwhPer100, analyzed`(13칸)
  - 없음은 빈 칸이다. `analyzed`는 1/0이다.
- 저장은 읽을 수 있는 줄 뒤에 새 줄을 붙이고, 마지막 100개만 남긴다(오래된 것과 깨진 줄은 버린다). 짧은 운전도 저장한다.
- 축·유형·코칭은 저장하지 않고, 읽을 때 지표로 다시 계산한다.
- 필드 수가 맞지 않거나 숫자를 읽을 수 없는 줄은 건너뛴다.

## 8. 화면 상태 (MainActivity)

우선순위는 위에서부터다.

1. **DRIVING**: 기어가 P가 아님
2. **TYPES**: 16유형 표(열림)
3. **RECORD**: 기록에서 고른 운전 다시 보기
4. **HISTORY**: 기록 목록(열림)
5. **FIRST**: 기록이 하나도 없음
6. **SHORT**: 마지막 운전이 짧은 운전
7. **RESULT**: 마지막 분석된 운전

- 페이지(TYPES, HISTORY, RECORD)는 한 번에 하나다. 칩을 누르면 다른 페이지는 닫힌다.
- 운전이 시작되거나 새 기록이 생기면 열린 페이지를 닫는다. 새 기록은 마지막 기록의 `endedAt`이 바뀐 것으로 안다(기록이 100개여도 동작).
- TYPES의 "이번 운전 유형"은 열기 직전에 보이던 RESULT·RECORD의 유형이다. FIRST·SHORT에서 열면 없다.
- DRIVING에서 Tracker가 그 운전을 세지 않으면(운전 도중 시작) 문구가 다르다(contracts §6).
- 앱이 가려지면(onPause)도 닫는다.
